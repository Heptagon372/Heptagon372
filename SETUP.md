# Setup — Heptagon372 profile README

Everything here goes into the special profile repo: **`Heptagon372/Heptagon372`**
(same name as the username — that's what makes GitHub show it on your profile page).

```
README.md                        ← the profile page
SETUP.md                         ← this file, delete it whenever
install.sh                       ← clones the repo, copies this in, pushes
assets/
  header.svg                     ← animated banner
  sec-*.svg                      ← the six section headers
  footer.svg                     ← wave footer
  stats.svg  langs.svg           ← regenerated by the Action
  streak.svg graph.svg           ← regenerated by the Action
.fonts/
  Orbitron.ttf JetBrainsMono.ttf ← used to draw text as paths (both OFL)
.github/
  scripts/gen_cards.py           ← builds the four stat cards
  scripts/make_banner.py         ← builds assets/header.svg
  scripts/make_sections.py       ← builds the section headers + footer
  scripts/text2path.py           ← shared font→SVG-path helper
  workflows/cards.yml            ← runs gen_cards.py every 6 hours
  workflows/snake.yml            ← builds the contribution snake
```

The four stat cards are committed in a neutral **"awaiting first Action run"**
state — no invented numbers ship. Step 2 below fills them in.

## 1. Push it

From inside this unzipped folder:

```bash
bash install.sh
```

It clones the repo, keeps the existing `README.md` as `PROJECT.md` (that repo
also holds the profile-site React app, and that file is its docs), copies
everything in, commits, and pushes.

By hand instead, if you'd rather:

```bash
git clone https://github.com/Heptagon372/Heptagon372.git
cd Heptagon372
git mv README.md PROJECT.md
cp -R /path/to/bundle/{README.md,SETUP.md,assets,.fonts,.github} .
git add -A && git commit -m "feat: new profile README" && git push
```

Your profile page updates the moment it lands on `main`.

## 2. Turn the two Actions on

Both need write access to the repo:

**Settings → Actions → General → Workflow permissions → Read and write permissions → Save**

Then run each one once by hand so you don't wait for the schedule:
**Actions → "Refresh profile cards" → Run workflow**, then the same for
**"Generate contribution snake"**.

The snake job pushes its SVGs to an `output` branch — that branch is created
automatically on the first run, and the README already points at it.

### Private commits in the numbers (optional)

By default the cards count public activity only. To include private work:

1. Create a classic PAT with `read:user` + `repo`
   (github.com → Settings → Developer settings → Personal access tokens → Tokens (classic)).
2. Repo → **Settings → Secrets and variables → Actions → New repository secret**
3. Name it `PROFILE_TOKEN`, paste the token.

The workflow picks it up on its own. Don't put the token anywhere else.

## 3. Editing things later

| What | Where |
|:--|:--|
| Your name / role / stack in the code block | `README.md`, the `const heptagon` block |
| Projects | `README.md`, the table under `sec-projects` — each cell is plain markdown |
| Tech icons | the `skillicons.dev/icons?i=...` URLs — full icon list at [skillicons.dev](https://skillicons.dev) |
| Typing lines | the `readme-typing-svg` URL — lines are `;`-separated and URL-encoded |
| Banner text / colours | `.github/scripts/make_banner.py`, then re-run it |
| Section titles | `.github/scripts/make_sections.py` — edit the `SECTIONS` list, re-run |
| Card design | `.github/scripts/gen_cards.py` — `--mock` renders sample data locally, `--pending` re-renders the blank state |

Regenerating locally needs `pip install "fonttools[woff]"` and nothing else.

## Why the stat cards are self-hosted

The usual hosted widgets were checked while this was built:

| Service | State |
|:--|:--|
| `github-readme-stats.vercel.app` | 503 — over quota |
| `github-profile-trophy.vercel.app` | Deployment Paused |
| `github-readme-activity-graph.vercel.app` | Deployment Paused |
| `readme-typing-svg.demolab.com` | OK |
| `skillicons.dev` | OK |
| `komarev.com` / `img.shields.io` | OK |

The three dead ones are shared free-tier deployments everyone hammers, so they
break regularly. `gen_cards.py` draws the same four cards from the GitHub
GraphQL API inside your own Action instead — no quota, no downtime, and the
styling matches the rest of the page.
